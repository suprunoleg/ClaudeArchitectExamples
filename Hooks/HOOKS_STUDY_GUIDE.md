# Claude Agent SDK: Hooks Certification Guide

This guide covers the most critical hooks and their properties tested on the Anthropic/Claude Architect Certification. Hooks allow you to deterministically intercept, modify, and control agent behavior at various lifecycle stages.

---

## 1. PreToolUse
Fires **before** a tool executes. This is your primary mechanism for security guardrails, human-in-the-loop approvals, and parameter manipulation.

### Important Return Properties
- **`permissionDecision`** (`"allow" | "deny" | "ask"`): Controls whether the tool is allowed to run. `"ask"` pauses execution to prompt a human for approval.
- **`permissionDecisionReason`** (`str`): An explanation for why a tool was denied. This is returned to Claude so it understands the rejection and can self-correct.
- **`updatedToolInput`** (`dict`): Replaces the arguments Claude passed to the tool before execution. Useful for forcing safe limits (e.g., forcing read-only paths).
- **`additionalContext`** (`str`): Appends extra context to the model's history without stopping execution.

### Exam Implementation
```python
def pre_tool_hook(event, matcher, context):
    query = event.tool_input.get("query", "").upper()
    
    # Example: Denying destructive action
    if "DROP" in query:
        return {
            "hookSpecificOutput": {
                "hookEventName": "PreToolUse",
                "permissionDecision": "deny",
                "permissionDecisionReason": "Destructive commands blocked by policy."
            }
        }
    
    # Example: Modifying input for safety
    if "LIMIT" not in query:
        return {
            "hookSpecificOutput": {
                "hookEventName": "PreToolUse",
                "permissionDecision": "allow",
                "updatedToolInput": {"query": event.tool_input["query"] + " LIMIT 10"}
            }
        }
        
    return {"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow"}}
```

## 2. PostToolUse
Fires **after** a tool completes but **before** the result is sent back to Claude. Primarily used for sanitization, normalization, and truncation.

### Important Return Properties
The `PostToolUse` hook has three completely different "audiences" you can talk to when returning data:

- **`updatedToolOutput` (Audience: Claude)**: Completely overrides the raw output generated by the tool. This is universal and works for both built-in SDK tools and MCP server tools. **(Highly tested on exams)**.
- **`additionalContext` (Audience: Claude)**: Appends extra notes or system hints alongside the tool output without destroying the original output.
- **`systemMessage` (Audience: Human User)**: Sends a message to the client/UI for the human user to read. Claude *never sees this message*, saving you context tokens while updating the human on long-running tasks.

> [!WARNING]
> **Exam Trap:** You may see `updatedMCPToolOutput` as an option. This is a **legacy** property that only works for MCP tools. `updatedToolOutput` is the modern, universal answer.

### Exam Implementation (The "Trinity" Example)
```python
def post_tool_hook(event, matcher, context):
    raw_output = event.tool_output # e.g., '{"user": "alice", "ssn": "123-45-678"}'
    
    # Data Sanitization
    sanitized_output = raw_output.replace("123-45-678", "[REDACTED PII]")
    
    return {
        "hookSpecificOutput": {
            "hookEventName": "PostToolUse",
            
            # 1. Talk to Claude: Replace the raw output with safe output
            "updatedToolOutput": sanitized_output,
            
            # 2. Talk to Claude: Add a hidden instruction
            "additionalContext": "Note to Claude: Sensitive PII was redacted from this response.",
            
            # 3. Talk to Human: Send UI Notification without using LLM tokens
            "systemMessage": "🔒 Security Notice: Redacted PII before sending logs to Claude."
        }
    }
```

## 3. UserPromptSubmit
Fires when the user submits a message, **before** the LLM sees it. Primarily used for injecting hidden environment variables or context.

### Important Return Properties
- **`additionalContext`** (`str`): Appends system data seamlessly to the user's prompt (e.g., current time, OS info, working directory).

### Exam Implementation
```python
def user_prompt_hook(event, matcher, context):
    # Automatically inject environment state without the user typing it
    context_str = f"System Time: {datetime.now()} | OS: {os.name}"
    
    return {
        "hookSpecificOutput": {
            "hookEventName": "UserPromptSubmit",
            "additionalContext": context_str
        }
    }
```

## 4. PreCompact
Fires when the conversation history has reached its token limit and is about to be truncated. 

### Important Return Properties
- **`additionalContext`** (`str`): Used to inject a summary of the truncated history or preserve vital "system instructions" so Claude doesn't forget them after old messages are wiped.

### Exam Implementation
```python
def precompact_hook(event, matcher, context):
    # Remind Claude of its core directive before history is lost
    vital_reminder = "Reminder: You are a strict JSON-only API assistant. Never output markdown."
    
    return {
        "hookSpecificOutput": {
            "hookEventName": "PreCompact",
            "additionalContext": vital_reminder
        }
    }
```

## The `HookMatcher` (Filter Property)
When configuring your `ClaudeAgentOptions`, you wrap your hooks in a `HookMatcher`. 

### Key Concept
- **`matcher`** (`str`): Acts as a filter. If you set `matcher="execute_sql"`, the hook **only** triggers when that specific tool is called. If omitted, the hook runs unconditionally for every instance of the event.

```python
options = ClaudeAgentOptions(
    hooks={
        "PreToolUse": [
            HookMatcher(
                matcher="execute_sql", # Only run this hook for execute_sql
                hooks=[my_security_hook]
            )
        ]
    }
)
```
